# EchoBuddy 听写、会议录音与语音设置方案

2026-11-21 · 设置稿与实施顺序

## 设置界面

[UI 设计规范](../../DESIGN.md)定义文字层级和控件尺寸。

[图一 · 浮窗设置下拉](../../design/settings/dropdown-settings-reference.png) · [图二 · 更多设置](../../design/settings/more-settings-reference.png)

- 点齿轮，在浮窗下方展开图一。顶部左侧是「设置」，右侧是「更多设置」入口。短听写模式显示「录音模式」「写入时机」「识别语言」。会议录音模式在同一位置显示「录音来源」，与短听写共用「录音模式」和「识别语言」。录音模式与写入时机各占一行，标题在左，右侧使用同尺寸、同底槽的分段按钮。点识别语言摘要，在按钮下方打开右对齐的勾选气泡，下方空间不足时向上展开。浮窗底部的更新区显示 EchoBuddy 版本和「检查更新」。
- 点「更多设置」打开图二的白底窗口，同时收起浮窗的设置下拉，回到工具条。左侧提供「语音」「会议记录」「个性化」「快捷键」「版本更新」。语音页的「写入时机」和「识别语言」沿用浮窗设置的布局和控件，下面是「我的声纹」和「自定义热词」。
- 两处界面共用同一份识别语言偏好。录音模式在浮窗下拉选择，听写和会议共用一个麦克风按钮，停录后可切换模式。两个模式按钮等宽等高，悬停显示各自的时长说明。短听写最长 2 分钟，到时自动停录并转写。会议录音最长 2 小时，到时自动停录并保存。
- 「快捷键」页分别设置「短听写快捷键」和「会议录音快捷键」。旧版组合键迁到短听写，会议录音默认使用 `Ctrl+Alt+Shift+R`，遇到旧组合键相同则用 `Ctrl+Alt+Shift+M`。各自直接开始对应模式，再按同一组停录。浮窗在录音期间显示实际使用的模式，停录后回到之前选中的模式。录入与另一组或外部应用冲突的组合键时，保留原设置。
- 验收检查点齿轮只展开下拉，点击「更多设置」才打开独立窗口，以及两处语言联动、侧栏导航、键盘操作及关闭行为。浮窗设置内的内容在纵向滚动条出现或消失时保持横向对齐。

## 逐项实施顺序

1. **浮窗下拉与更多设置。** 按图一、图二实现两层设置入口，验证分组标题、侧栏切换、关闭和焦点行为。
2. **会议录音。** 接入麦克风、电脑声音和双轨录音，验证两小时录音和中断后恢复。
3. **会议转写时间轴。** 验证点击转写能跳到录音对应位置，并保存模型返回的识别结果。
4. **流式输入。** 验证确认段落能顺序写入原应用，停止时不重复，切换目标时保留余下文字。
5. **识别语言。** 验证设置持久化、单语识别和多选后的候选语言范围。
6. **用户自定义热词。** 先用同一批样音比较支持热词的模型，再接用户填写的词库。
7. **声纹。** 在「更多设置 → 语音」录入、验证和删除本机声纹。会议转写可按当前声纹标注「我」。

## 两小时会议录音

### 录音来源

在浮窗「设置 → 录音模式」选中「会议录音」后，出现「录音来源」。麦克风和电脑声音是两个可独立勾选的选项，至少选一项。首次默认勾选麦克风。录音期间显示已选音源并锁定选择。

| 选择 | 适用场景 | 录到的内容 |
| --- | --- | --- |
| 仅麦克风 | 现场会议 | 现场进入麦克风的声音 |
| 麦克风和电脑声音 | 戴耳机参加线上会议 | 麦克风与播放设备各录一轨 |
| 仅电脑声音 | 单独记录电脑播放的内容 | 当前默认播放设备输出的声音，包括耳机播放和系统提示音 |

### 开录、停录和查看

- 选中会议录音后点麦克风，或直接按会议录音快捷键开录。浮窗显示「录音中」、计时和停止按钮，贴边收起后仍可计时和停录。最长 2 小时，到时自动停止并保存。
- 开录前检查所选音源。启动失败时提示具体音源，由用户选择重试或调整选项。双轨录制中一路断开时提示哪一路中断，并记录该路的时间缺口。另一路继续保存。全部音源中断时，自动停录并保留已录内容。
- 在「更多设置」左栏打开「会议记录」。会议模式下的浮窗气泡和 Windows 托盘的「会议记录」可直接到达同一页。还没有录音时显示「暂无会议记录」。
- 停录后浮窗显示「录音已保存」和「查看会议」。点「查看会议」会进入同一个设置窗口并选中刚保存的会议，录音可以立即回放。列表按日期分组，显示会议标题和当前处理状态，转写完成后显示时长。详情提供回放、「打开录音文件夹」和「重试转写」，后者从最近已保存的片段继续处理。
- 点击会议详情的标题，在原位编辑名称。按 Enter 或点击输入框外保存，会议列表同步更新。按 Esc 取消，空名称保留原名。编辑前后标题区域占用相同空间。
- 「打开录音文件夹」右侧提供「删除录音」。确认后，这场会议的录音和转写一起移到 Windows 回收站，列表同步更新。若这条记录正在转写，先停止该任务再移动文件。

### 采集、保存与恢复

- 会议通过独立的 Windows 录音组件采集。麦克风使用 Windows 默认输入设备，电脑声音通过 WASAPI 从开录时的默认播放设备采集。两路使用同一个时钟，在浮窗界面重新加载时继续录制。 [Windows 回环录音](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
- 文件保存在本机的 `%LOCALAPPDATA%\EchoBuddy\Meetings\<会议 ID>`。每个所选来源保存一份完整的 WAV，麦克风为 `microphone.wav`，电脑声音为 `system.wav`。WAV 采用 16 kHz 单声道 PCM16，两小时约 230 MB 每轨，双轨约 461 MB。音频共用会议时间轴，静音和断流缺口按原时长保留。
- `meeting.json` 记录会议时间、音源、时长和处理进度，`transcript.jsonl` 按共同的音频时间范围提交转写。录音约每 5 秒写回 WAV 文件头并同步到磁盘。正常退出会先保存正在进行的会议。异常退出后重新启动，应用修复 WAV 长度、对齐双轨，并从上次提交继续转写。

## 会议转写时间轴和识别结果

- 复用现有 SenseVoice 引擎，在独立的本机后台进程逐段转写。只启用一种识别语言时，将该语言交给模型。多选时使用模型的自动检测。每段记录会议内的起止时间、所属音源和文字，时间按原始采样位置换算。
- 会议详情页在播放器下方按时间排列转写。点一段时间从对应位置播放，两路录音按同一进度合起来听。音源标签显示「麦克风」或「电脑声音」。外放导致两轨都收到同一句时，转写列表合并重复内容，原始音轨保存在会议记录中。
- 有至少 3 秒有效人声并匹配本人声纹的段落标「我」。其他说话人按模型分组累计人声，达到 1.2 秒且分组可区分时，在同一场会议统一标识为 A／B 等。重叠或证据不足的段落保留可识别的文字并标「未确认」。
- 识别结果可带语言、情绪、声音事件和模型 token 时间戳。有值时保留相应字段。首版界面先验证时间轴，语言、情绪和声音事件的显示规则待定。纯声音事件会受 VAD 切分影响，需要样音验证。

### 首版验收

1. 现场仅开麦克风、耳机线上双轨、仅录电脑声音各做一次回放，核对录入声音与选项相符。
2. 连续录满 2 小时后自动保存。模拟录音中退出和耳机断开，核对已录音频可播放，转写能从断点继续。
3. 在长静音后和录音末尾抽查单击转写时间的回放位置。双轨在会议末尾仍能对齐，外放串音时同一句转写合并。
4. 用双人轮流讲话样音确认「我 → 说话人 A → 我」的标签前后一致。用重叠样音检查「未确认」。

2026-11-22 的 Windows 验收覆盖三种录音来源、电脑声音实录样音、贴边计时和停录、托盘历史、时间轴双轨同步跳播、转写重试，以及正常退出保存和打包版本强退后的播放恢复。双人合成样音验证了跨时间段的「我」和「说话人 A」。自动停录和断流分支通过缩短录音上限、模拟一路断开验证，并检查了两小时 WAV 的文件头和末尾分段读取。连续实录 2 小时和实物耳机插拔仍待验收。

## 设置里的听写方式

- 听写模式可选「流式输入」或「整句写入」。前者让已确认的文字在录音期间按段写入原应用的输入框，后者在按下停止后一次性写入，设计稿以此作为默认值。识别中的草稿仍可在转写气泡中查看。
- 每次写入前确认目标输入框和插入位置。用户切换窗口、移动光标或目标失效时，暂停对外写入，将未写入文字留在气泡中。停止时只处理还未写入的段落。
- 停录后可在「本次转写」标题右侧点「清空」，移除这次气泡里的转写和待写入文字。气泡保持打开并显示「暂无转写内容」。
- 验收用连续两段口述确认先出第一段、再追加第二段，停止时无重复。还要验证切换窗口后文字留在气泡里，原位置以外的输入框没有收到内容。

## 设置里的识别语言

- 提供普通话、英语、粤语、日语、韩语多选，至少启用一项。界面用「识别语言」表示可选范围，五种语言共用内置 SenseVoice 模型文件。
- 只启用一种语言时可以显式指定给模型。任意多选组合需要补受限的语言识别或路由。当前 `auto` 接口本身没有可配置的候选语言列表。
- 验收验证设置重启后仍然有效、单语选择生效，以及选择普通话和英语时其余语言被排除在自动识别候选之外。中英混说单独用样音验证。

## 用户自定义热词

- 用户在详细设置中输入和删除自己常用的人名、术语和品牌名。添加时只填期望的写法，例如「OnoSan」，词库保存在本机。
- 对应的识别能力是在解码时提高自定义词的优先级。中英 Zipformer 可以使用现有 sherpa-onnx 运行库，SeACo-Paraformer 可以作为中文定稿对照。用包含目标词和不含目标词的样音，分别验证命中、误识别和延迟。 [sherpa-onnx 热词](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html) · [FunASR 模型接口](https://github.com/modelscope/FunASR/blob/main/docs/python_api.md#language-hotwords-and-alignment-are-model-specific)
- 识别后纠错可沿用 SenseVoice，依赖「常见误写 → 正确词」的映射规则，适合作为固定误写场景的对照。

## 本机声纹

- 用户跟读三条不同的录入样本，再读一条独立验证语句。每条至少包含 3 秒人声，最长录 20 秒。验证通过才替换现有声纹。Windows 加密保存在本机的数据只包括声纹向量和模型版本。在语音页可重新录入或删除。
- 短样音已验证 pyannote 切分、CAM++ 比对声纹和 SenseVoice 转写。会议沿用这些模型，后台转写可读取已录入的本机声纹进行匹配。

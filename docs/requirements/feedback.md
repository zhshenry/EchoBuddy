# 问题反馈

浮窗设置 → 问题反馈 → 前往反馈，或更多设置 → 问题反馈。填写 → 预览 → 确认发送；诊断仅含版本、系统和最近结构化操作，不自动读取转写、录音、声纹、用户文件或聊天。

三产品共用私有 zhshenry/onosan-feedback，EchoBuddy 带 product:echobuddy 标签。预览、本机保存、复制和导出不会发送。失败保留同一反馈编号，可查询后重试；历史可重开查看状态。已提交与已解决分开显示。

2026-11-25 已完成隔离 Electron 实窗预览、脱敏、导出、真实提交、历史及 780×800 窄窗验证；合成测试单 #5 已核对标签并关闭。未发布安装包，未改动 Grok 定时任务。服务及协议说明维护在 ONOSAN 的 tooling/feedback-receiver/README.md。

## 内网转交（2026-11-25）

- 页面提供「自动选择／在线提交／内网转交」，手动选择保存在本机并优先于自动检测。显示检测结果、检测时间、发送位置及「重新检测」。
- 自动选择使用 AI HUB 的只读 OpenX 发布列表作为公司网络探测。仅 HTTP 成功且 JSON code=0、data.records 为数组时确认可达，登录网页、代理错误及超时不视为公司网络。独立探测公网接收端 /health；公司网络可达时优先内网，否则公网可达走原在线提交，两者均未确认时只保留本机反馈。
- 两个探测均限时 10 秒，只传固定查询参数，不上传反馈内容。结果在内存缓存 10 分钟，程序启动和进入反馈页时检测；页面打开期间每 30 秒核对网络接口变化，并在网络事件、页面重新获焦点或手动重新检测时核对。接口地址仅用作内存缓存键，不进入反馈包。提交时重新核对当前通道，变化后要求用户再次确认。
- 内网维护人固定为 z00545972。用户预览同一份脱敏摘要后，点「确认发送摘要」才调用 WeLink。完整原始反馈包先保存到系统下载文件夹 echobuddy-feedback-<编号>.json，再发送不超过 1450 个 UTF-16 码元的摘要。用户仍需把 JSON 文件在 WeLink 发给维护人，由维护人在外网使用已有接收工具导入原反馈编号，最终进入私有反馈仓库。
- WeLink 命令行仅使用应用资源/vendor、已安装的 WeClaw 工具或 PATH 中现有的 welink-cli.exe，不新增安装包依赖。发送前只读检查登录，使用 execFile 参数数组执行，隐藏命令行窗口。缺少工具或登录不可用时可「复制摘要并打开 WeLink」，同时保存反馈包；协议未注册时提示手动打开。自动登录、自动发送附件不在本次范围内。
- 只有明确成功回执才显示「摘要已发送，反馈包待转交」。超时、回执不可解析或发送途中进程中断都保持送达未知，不自动重复发 IM，不自动切到公网。复制/保存仍不标记发送成功。在线提交和转交都保留同一反馈编号。内网记录可手动「查询处理状态」，外网服务尚无该编号时保留本机包，导入后显示原云端状态；内网访问不到公网时查询保留原记录，不声称已有处理进展。
- 验证：新增网络路由、缓存、手动覆盖、登录、消息回执、包先落盘、同编号查询与去重的自动测试。隔离 Electron 已验证实际 IPC、页面选择、摘要与预览一致、公网提交、手动转交、失败保留、送达未知及 382×520 窄窗；测试使用模拟网络和 WeLink，真实公司网络和真实 WeLink 收信仍需在公司电脑验收。本次没有发送真实消息或反馈，未发布。
